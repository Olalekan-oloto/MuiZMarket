MUIZMARKET — REAL ACCOUNTS, GOOGLE/APPLE SIGN-IN, PROFILE SETTINGS
==================================================================

What this package adds
- Email/password Create Account, Sign In, and Forgot Password.
- Continue with Google using Firebase's mobile-friendly redirect flow.
- Continue with Apple using Firebase OAuth (requires Apple Developer configuration).
- On first Google/Apple sign-in, use the provider's display name as the full name and create a suggested unique username.
- Redirect new social-login users to Profile Settings to finish country, phone number, date of birth, and username.
- Profile Settings to update name, username, country, phone, date of birth, and profile picture.
- Firebase Storage upload rules for profile pictures (JPG/PNG/WebP, under 5 MB).
- Buyer is the default account role. Seller/admin privileges must be granted/approved by trusted backend logic, never by client-side form fields.

A. FINISH FIREBASE SETUP
1. Open https://console.firebase.google.com/ and select the correct MuiZMarket project.
2. Project settings (gear icon) -> General -> Your apps. Select the web app or add one (</>).
3. Copy the complete web config. In firebase-config.js, fill apiKey, authDomain, projectId, storageBucket, messagingSenderId and appId. Measurement ID is optional.
4. Authentication -> Sign-in method (sometimes shown under Build -> Authentication):
   - Enable Email/Password.
   - Enable Google. Choose a project support email if prompted.
   - Enable Apple only after completing the Apple Developer configuration in section C.
5. Authentication -> Settings -> Authorized domains. Add:
   olalekan-oloto.github.io
   Keep the project's Firebase authDomain too. If your Pages site uses a different exact hostname, add that hostname.
6. Build -> Firestore Database -> Create database, preferably production mode.
7. Firestore -> Rules: replace with the contents of firestore.rules in this package and Publish.
8. Build -> Storage -> Get started. Set up the bucket, then Storage -> Rules: replace with storage.rules and Publish. If Firebase asks for a billing-plan upgrade for Storage, do not proceed unless you understand the plan and costs; profile-photo upload will not work until Storage is available.
9. Authentication email templates: review the verification and password-reset messages before opening registration to public users.

B. GOOGLE SIGN-IN
1. In Firebase Authentication -> Sign-in method, enable Google and save.
2. Make sure olalekan-oloto.github.io is in Authorized domains.
3. Deploy the website to GitHub Pages over HTTPS.
4. Tap Continue with Google on account.html. On Android, Firebase redirects to Google's sign-in screen, then returns to MuiZMarket.
5. On first sign-in, the profile is created from the Google account name and the user is sent to settings.html to complete remaining details.

C. APPLE SIGN-IN (MORE SETUP REQUIRED)
Apple sign-in cannot be activated only by adding a button. Firebase requires an Apple Developer Program account and Apple-side identifiers/keys.
1. In Apple Developer, configure Sign in with Apple for a website and create a Services ID.
2. Register this Firebase return URL with Apple:
   https://YOUR_FIREBASE_PROJECT_ID.firebaseapp.com/__/auth/handler
   Replace YOUR_FIREBASE_PROJECT_ID with the actual project ID (for the project in the screenshot, it would be mick-stream only if that is the project you use).
3. Create an Apple Sign in private key. In Firebase Authentication -> Sign-in method -> Apple, enter the Services ID, Apple Team ID, Key ID and private key as requested.
4. If Firebase emails must reach Apple private relay addresses, follow Apple's email-relay setup instructions for Firebase's sender address.
5. Save and test on HTTPS. Apple may provide the user's name only the first time they authorize the app; the account profile stores it for later visits.
6. If you do not have the required Apple Developer setup yet, the Apple button will show a configuration error until you finish it. Google and email/password can be configured separately.

SECURITY AND LIMITATIONS
- Firebase Authentication stores passwords; MuiZMarket does not store raw passwords in Firestore.
- Google/Apple authentication proves control of that provider account; it does not verify the user's phone number.
- Phone and date of birth are stored as profile data and should be collected only if needed. Publish a privacy notice and restrict profile access.
- The Storage rule allows anyone to read profile picture files for public profile display, but only that same signed-in user can upload/replace their own picture.
- Do not put service-account JSON, Firebase Admin private keys, or privileged API secrets in GitHub Pages files.
- The client-side code never grants admin privileges. Seller approval, subscriptions, payments, orders, withdrawals and other marketplace financial operations still require a trusted backend. GitHub Pages cannot run server.js.


ACCOUNT ROLES, COUNTRIES, AND SELLER VIDEO PREVIEW
- The Create Account form now lets a new user choose Buyer or Seller. After account creation, the site redirects to the matching dashboard. Email verification is still required before protected account actions.
- Country choices use the full ISO country list. Phone input uses intl-tel-input from a CDN, with a selectable international dialing code; keep an internet connection available.
- The seller dashboard includes a local video preview button. This only previews a selected video in the browser; it does NOT upload or publish a product. Secure product video uploads/listing moderation require the deployed API and explicit Storage rules.
- Owner dashboard: open support-inbox.html. Access is not granted by a page link: configure your own Firebase Auth UID in the backend ADMIN_UIDS environment variable and deploy server.js. Never make admin access depend on a user-editable profile field.
- Google sign-in currently creates a buyer profile by default unless the user later selects a role in the email registration form. Apple sign-in must be separately enabled and configured in Firebase and Apple Developer settings.
